프로젝트 전체 쉽게 보기

최신 버전 · 2026-10-12

우리 팀이 무엇을, 왜, 어떤 순서로 만드는지 주방 이야기로 설명합니다. 1~3번 팀원도, 처음 보는 사람도 읽을 수 있습니다.

다음 문서: 02 검증·평가 파트 상세 (4번 담당의 할 일)

이것 세 줄만 기억해도 됩니다

  1. AI는 옛날 주방만 기억해서, 도구가 이사 간 줄 모르고 옛날 레시피를 줍니다.
  2. 우리 프로그램은 새 주방 안내서를 보고 레시피를 고친 뒤, 서랍을 직접 열어 보며 도구가 있는지 확인합니다.
  3. 나(4번)는 요리 대회 심사위원입니다. 같은 문제 30개로 "우리가 더 잘 고친다"를 숫자로 증명합니다.

1장

프로젝트 전체를 주방으로 이해하기

프로그램을 만드는 일은 요리와 비슷합니다. LangChain은 AI 프로그램을 만들 때 쓰는 주방 도구 세트입니다. 그리고 코드 맨 위에 쓰는 import는 "어느 서랍에서 어떤 도구를 꺼내라"는 뜻입니다.

# 코드로 쓰면
from langchain.chat_models import ChatOpenAI

# 주방 말로 바꾸면
"langchain 서랍장의 chat_models 칸에서 ChatOpenAI 도구를 꺼내라"

그런데 2025년에 LangChain 1.0이 나오면서 주방 정리를 새로 했습니다. 도구들이 다른 서랍으로 이사를 갔고, 일부는 창고로 치워졌습니다.

도구옛날 위치지금 위치
ChatOpenAI (AI 모델 연결)langchain.chat_modelslangchain_openai 서랍으로 이사
PromptTemplate (질문 틀)langchain.promptslangchain_core 서랍으로 이사
LLMChain (옛날 조립 방식)langchain.chains창고(langchain_classic)로 치워짐. 요즘은 prompt | llm으로 조립
initialize_agent (옛날 에이전트)langchain.agents없어짐. 요즘은 create_agent 사용

옛날 레시피대로 옛날 서랍을 열면 이렇게 됩니다. 이건 실제로 최신 LangChain(1.4.4)에서 실행한 결과입니다.

from langchain.chat_models import ChatOpenAI
ImportError: cannot import name 'ChatOpenAI'   ← "그 칸에 그런 도구 없어요"

from langchain.chains import LLMChain
ModuleNotFoundError: No module named 'langchain.chains'   ← "그런 칸 자체가 없어요"

문제: 옛날 주방만 기억하는 요리사

ChatGPT 같은 AI는 인터넷 글을 많이 읽고 배웠습니다. 그런데 인터넷에는 옛날 주방 레시피가 훨씬 많습니다. 그래서 AI는 옛날 서랍 위치를 알려 주고, 자기가 틀린 줄도 모릅니다. 이걸 "버전 지체 환각"이라고 부릅니다.

해결: 안내서를 보고, 서랍을 직접 열어 보는 도우미

일반 AI

기억에 의존해서 레시피를 고칩니다. 서랍을 열어 보지 않으니 틀려도 모릅니다.

우리 프로그램

① 새 주방 안내서(공식 문서)를 찾아보고 고칩니다. ② 서랍을 직접 열어 봅니다(import 실행). 도구가 없으면 다시 찾아보고 고칩니다.

①을 문서 근거, ②를 실행 근거라고 부릅니다. 두 가지로 확인한다고 해서 "이중 검증"입니다. 이게 우리 프로젝트의 핵심입니다.

헷갈리기 쉬운 점

우리 프로그램은 주방을 정리하지 않습니다. 새 주방은 LangChain 회사가 이미 정리해 두었습니다. 우리 프로그램이 고치는 것은 레시피(사용자의 코드)입니다. "옛날 서랍 A에서 꺼내라"를 "새 서랍 B에서 꺼내라"로 고쳐 쓰고, B를 열어 보며 도구가 진짜 있는지 확인합니다.

2장

기본 설계: 프로그램은 어떤 순서로 일하나

기본 설계는 앞에서부터 보는 방법입니다. 사용자가 옛날 레시피(코드)를 넣으면, 프로그램 안에서 다섯 명의 직원이 차례로 일합니다.

① 담당 3번analyzer레시피를 읽고 "이 도구들, 이사 갔을 수도 있어" 표시
② 담당 2번retriever새 주방 안내서에서 도구의 새 위치 찾기
③ 담당 3번rewriter안내서를 보고 레시피 고쳐 쓰기
④ 담당 1번verifier새 주방에서 서랍을 직접 열어 보기
⑤ 담당 3번report고친 레시피 + 안내서 몇 쪽 + 몇 번 만에 성공

④에서 도구가 없으면 → 에러 메시지를 들고 ②로 돌아가 다시 찾습니다. (최대 3번)

이 되돌아가는 길을 검증 루프라고 합니다. 일반 AI에는 이 길이 없습니다. 그래서 틀려도 그냥 끝납니다.

팀원 역할도 이 그림으로 이해됩니다

1번은 직원들을 줄 세우고 연결합니다(그래프·백엔드, verifier). 2번은 안내서를 준비하고 찾아 줍니다(데이터·검색). 3번은 읽고, 고쳐 쓰고, 답을 씁니다(변환·화면). 4번(나)은 이 직원들이 일을 잘하는지 시험하고 점수를 매깁니다.

역설계: 발표 장면에서 거꾸로 내려가기

역설계는 뒤에서부터 보는 방법입니다. "마지막에 무엇을 보여줄까?"를 먼저 정하고, "그걸 하려면 뭐가 필요하지?"를 계속 물으며 내려갑니다.
