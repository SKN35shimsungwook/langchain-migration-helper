# 역할 분담표

> 기준일: 2026-10-13 · 팀 회의용 한 장 요약
> 한 줄 원칙: **1번은 "연결", 3번은 "각 단계의 내용", 2번은 "근거 자료", 4번은 "보여 주기와 증명"**

## 1. 네 역할 한눈에

| 번호 | 역할 | 한마디 | 맡는 것 | 주요 산출물 | 주방 비유 |
|---|---|---|---|---|---|
| **1번** | 그래프 · 백엔드 | 뼈대와 배선 | State 정의(`MigrateState`), LangGraph 연결, 재시도 조건(최대 2~3회), `run_migration()` 함수(HTTP는 선택), 실행 로그, 샌드박스 환경 설치 | `src/graph/`, 폴더 구조 | 주방 동선과 주문 전달 체계 |
| **2번** | 데이터 · 검색 | 근거 자료 | 마이그레이션 가이드·릴리스 노트 수집, 청킹, 임베딩, Qdrant 저장, `symbol_map.json`, retriever | `data/`, Qdrant, `symbol_map.json` | 새 주방 안내서 만들기와 찾아 주기 |
| **3번** | 변환 · 검증 | 각 단계의 실제 일 | analyzer, rewriter, **verifier**, report (report 노드는 4번이 맡을 수도 있음, 회의에서 확인) | `src/agents/`, 프롬프트 | 요리사와 검수원 |
| **4번** | 화면 · 평가 | 보여 주기와 증명 | **Streamlit 화면**, 평가 설계, 테스트셋, 비교 실험, 그래프 + **보고서 · README · 발표** | `app.py`, `eval/`, `docs/`, 발표 자료 | 손님 테이블과 요리 대회 심사위원 |

## 2. 전체 구조에서 각자의 위치

```text
[오프라인, 1회]  ─────────────────────────────────────────── 2번
  가이드·릴리스 노트 수집 → 청킹 → 임베딩 → Qdrant 저장
  → symbol_map.json (구 심볼 → 신 심볼, 근거 ID)

[온라인, 요청마다]  파이프라인 연결 · 재시도 조건 · API ────── 1번
  ① analyzer   ast로 import·클래스·함수 심볼 추출 ────────── 3번
  ② retriever  symbol_map 조회 + Qdrant 검색 (+ 에러 피드백) ─ 2번
  ③ rewriter   LLM이 {새 코드, 변경 목록(근거 ID)} 출력 ───── 3번
  ④ verifier   (a) 근거 ID 확인 (b) 샌드박스 import·속성 검증 ─ 3번
               └ 실패하면 에러 종류·대상을 피드백으로 ②로 (최대 2~3회)
  ⑤ report     변환 코드 + 변경표 + 시도 횟수 ────────── 3번 (또는 4번)

[파이프라인 바깥]
  화면   한 건씩: 목표 버전 + 코드 입력 → report 결과 보여 주기 ── 4번
  평가   30건 한꺼번에: 파이프라인 vs 일반 AI 성공률 비교 ──── 4번
```

## 3. 1번과 3번의 경계 (가장 헷갈리는 부분)

| 구분 | 1번 (연결) | 3번 (내용) |
|---|---|---|
| State | 모양을 정의 | 정해진 칸에 값을 채움 |
| 단계 순서 | analyzer → … → report 연결 | 각 단계 함수 안의 로직 |
| 되돌아가기 | **다시 갈지 판단** (조건부 엣지, 횟수 세기, 한도에서 종료) | **통과/실패와 피드백만 기록** |
| 샌드박스 | 검증용 환경 **설치·관리** | 그 안에서 **무엇을 검사할지** |
| API | 만듦 | 관여 안 함 |

**약속**: 모든 단계는 같은 모양의 함수로 만든다.

```python
# 3번: 단계의 내용
def verifier(state: MigrationState) -> dict:
    ...  # (a) 근거 ID 확인, (b) 샌드박스 검증
    return {"verify_result": {...}, "feedback": {...}}

# 1번: 연결
graph.add_node("verifier", verifier)
graph.add_conditional_edges("verifier", 다시_할지_판단, {"retry": "retriever", "done": "report"})
```

## 4. 서로 맞춰야 하는 것 (접점)

| 무엇 | 쓰는 쪽 | 읽는 쪽 | 정할 내용 | 언제 |
|---|---|---|---|---|
| **State 필드** | 1번 | 모두 | 필드 이름과 모양. 팀 저장소에 `MigrateState(old, new, evidence_id, kind)`가 있음 → symbol_map 합의안 0장에 연결표 | 첫날, 이후 고정 |
| **에러 피드백** | 3번 (verifier) | 2번 (retriever) | `{에러 종류, 대상 심볼, 메시지}` | 첫날 |
| **symbol_map · 근거 ID** | 2번 (Qdrant, symbol_map) | 3번 (rewriter, verifier), 4번 (화면 링크, 평가 대조) | [symbol_map_합의안.md](symbol_map_합의안.md) — 이사 목록 모양, 근거 ID 규칙 `문서#섹션-번호`, Qdrant payload | 지금 (합의안 보냄) |
| **report 출력 모양** | 3번 | **4번 (화면, 평가)** | [출력모양_합의안.md](출력모양_합의안.md) — 변환 코드, 변경표(구 → 신, 근거 링크, 근거 확인), 검증 결과, 시도 기록 | 지금 (합의안 보냄) |
| ~~verifier 결과 모양~~ | – | – | report 안에 시도 기록과 근거 확인이 들어 있어서, 평가 결과는 4번이 `eval/run_system.py`로 report에서 직접 계산. **따로 합의할 필요 없음** | – |
| **판정 기준** | 4번 (`eval/verify.py`) | 3번 (verifier (b)) | 같은 기준으로 판정해야 평가가 공정함. `verify.py`를 verifier의 출발점으로 넘김 | 바로 |
| **그래프 호출 방법** | 1번 | 4번 (화면, 평가) | [API_합의안.md](API_합의안.md) 1.1 — 기본 `run_migration(code, target_version) → report` 함수, 선택 HTTP(`POST /migrate` 등) | 13:40 회의 |
| **목표 버전** | 4번 (화면) | 1번 · 3번 | `target_version` (지금은 `"1.x"` 하나) | 13:40 회의 |

## 7. 팀 저장소에 넣을 자리 (계획)

팀 저장소는 1번이 만든 구조(`app.py`, `src/agents`, `src/graph`, `src/rag`, `data/`)를 따릅니다. 4번 결과물은 **1번에게 확인받은 뒤 4번이 직접** 4번 브랜치에 옮기고 dev로 PR합니다. 이 개인 저장소의 작업은 팀 저장소를 건드리지 않습니다.

| 개인 저장소 | 팀 저장소 |
|---|---|
| `app/streamlit_app.py` | `app.py` |
| `app/backend.py` | `src/ui/` |
| `eval/` | `eval/` |
| `docs/` 합의안 · 예시 | `docs/` |
