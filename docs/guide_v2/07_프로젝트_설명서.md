# 프로젝트 설명서

> **최신 버전 · 2026-10-13** · 기준: 팀 저장소 **dev(1번 폴더 구조)** + **2번 브랜치(데이터 · 검색)**, 읽기만 해서 정리  
> 웹에서 보기: [HTML](https://skn35shimsungwook.github.io/langchain-migration-helper/docs/guide_v2/07_프로젝트_설명서.html) · 인쇄용: [PDF](07_프로젝트_설명서.pdf)  
> 이 저장소의 예전 연습 초안(시험지, 화면, 합의안)은 **참고하지 않았습니다.** 팀원은 **역할 번호(1~4번)**로만 적습니다.

## 이것 세 줄만 기억해도 됩니다

1. 챗봇은 **옛 LangChain 코드를 받아 → 2번 데이터에서 근거를 찾고 → 3번이 고치고 확인해서 → 결과를 돌려주는** 흐름입니다. 1번은 이 흐름을 잇는 **뼈대**입니다.
2. 지금 팀은 **1번 뼈대가 시작 단계, 2번 데이터 · 검색이 거의 완성, 3번 · 4번은 시작 전**입니다.
3. 4번은 **챗봇 바깥**에서 일합니다: 결과를 보여 주는 **화면**, 일반 AI와 비교하는 **평가**, 그리고 **보고서 · 발표**입니다. 당장은 **챗봇 없이도 되는 평가 준비**부터 합니다.

## 1장. 내 이해도 점검 결과

설명서를 쓰기 전에 네 가지를 물었습니다.

| 질문 | 내 답 | 판정 |
|---|---|---|
| 챗봇이 하는 일 | 옛 코드를 최신으로 고쳐 줌 | ✅ 정확 |
| 2번의 import 대응표 | 옛 위치 → 새 위치 목록 | ✅ 정확 |
| 3번과 4번의 차이 | 3번은 챗봇 속, 4번은 바깥 | ✅ 정확 |
| 자세히 알고 싶은 것 | 큰 그림과 4번 역량, 전체 흐름, 1번 폴더 · 2번 데이터, 당장 할 일, 용어 | → 2~10장 |

**결론**: 기본 개념은 이미 잡혀 있습니다. 부족한 것은 **"실제 팀 파일에서 그게 어디에 있고, 어떻게 이어지는지"**입니다. 그래서 이 설명서는 **실제 예시 하나를 따라가며** 설명합니다.

## 2장. 큰 그림

![전체 구조](../images/08_system_v2.svg)

| | 내용 |
|---|---|
| **문제** | ChatGPT 같은 AI에게 옛 LangChain 코드를 고쳐 달라고 하면, AI는 **옛 버전만 기억**해서 틀린 코드를 주고, 틀린 줄도 모릅니다 |
| **해결** | ① 최신 문서와 이사 목록에서 **근거를 찾아** 고치고 ② 고친 코드를 **실제로 실행해 확인**하고 ③ 틀리면 **다시 찾아 다시 고침** |
| **증명** | 같은 옛 코드 여러 개를 **일반 AI**와 **우리 챗봇**에 넣고, 같은 기준으로 **성공률을 비교** (4번) |

**주방 비유**: LangChain은 도구 세트, import는 "몇 번 서랍에서 도구를 꺼내라", 버전 업데이트는 **도구가 다른 서랍으로 이사 간 것**입니다. 2번은 **이사 목록과 안내서**, 3번은 **레시피를 고치고 서랍을 직접 열어 확인하는 요리사**, 1번은 **주방 동선**, 4번은 **손님 테이블과 심사위원**입니다.

## 3장. 전체 흐름: 예시 하나 따라가기

사용자가 아래 옛 코드를 넣었다고 해 봅시다.

```python
from langchain.chat_models import ChatOpenAI
from langchain.chains import LLMChain
from langchain.prompts import PromptTemplate
```

| 단계 | 하는 일 | 이 예시에서 | 담당 · 팀 파일 | 지금 상태 |
|---|---|---|---|---|
| ① analyzer | 코드에서 import 경로 뽑기 | `langchain.chat_models.ChatOpenAI` 등 3개 | 3번 · `src/agents/analyzer.py` | 빈 파일 |
| ② retriever | 이사 목록에서 새 위치 찾기 + 문서 검색 | 아래 표 (2번 검색기를 **실제로 돌린 결과**) | 2번 · `src/rag/retrieval/` | ✅ 있음 |
| ③ rewriter | 근거를 보고 AI가 코드 다시 쓰기 | `ChatOpenAI`는 새 서랍으로, `LLMChain`은 `prompt \| llm`으로 | 3번 · `src/agents/rewriter.py` | 빈 파일 |
| ④ verifier | 새 코드를 실제로 실행해서 확인. 실패하면 ②로 (실패한 근거는 빼고, 범위를 넓혀) | import 성공? 기능 이름 있음? | 3번 · `src/agents/verifier.py` | 빈 파일 |
| ⑤ report | 새 코드 + 바뀐 곳 + 근거 + 시도 횟수 정리 | 화면에 보여 줄 결과 | 미정 (3번 또는 4번) · `src/agents/report.py` | 빈 파일 |
| 연결 | ①~⑤를 순서대로 잇고, ④에서 다시 갈지 판단 | – | 1번 · `src/graph/supervisor.py` | 틀만 있음 |
| 화면 · 평가 | 사용자에게 보여 주기, 일반 AI와 비교 | – | **4번** · `app.py`, (평가 폴더 새로) | 시작 전 |

**② 2번 검색기를 실제로 돌린 결과** (API 키 없이 되는 "이사 목록 찾기" 부분)

| 옛 위치 | 새 위치 | 종류 | 근거 ID | 대안 |
|---|---|---|---|---|
| `langchain.chat_models.ChatOpenAI` | `langchain_openai.ChatOpenAI` | native (최신 방식) | `imap-02229b7d73` | – |
| `langchain.chains.LLMChain` | `langchain_classic.chains.LLMChain` | classic_fallback (옛 창고) | `imap-41c19d624a` | `prompt \| llm` |
| `langchain.prompts.PromptTemplate` | `langchain_core.prompts.PromptTemplate` | native | `imap-8ed4309a81` | – |

**읽는 법**: `LLMChain`은 1.x에서 없어져서 옛 창고(classic)에만 남았습니다. 그래도 2번이 **대안(`prompt | llm`)**을 같이 적어 두어서, 3번 rewriter가 최신 방식으로 바꿀 수 있습니다. 검색기는 이 대안으로 **문서도 더 찾아서** 함께 넘겨줍니다.

## 4장. 팀 저장소 실물 지도

### 1번이 만든 폴더 구조 (dev)

```text
SKN35-3rd-4Team/
├── app.py              print('Hello World!')   ← 화면 자리 (4번)
├── pyproject.toml      필요한 패키지 목록 (uv)
├── .env.example        OPENAI_API_KEY 자리 (각자 .env 를 만들어 키를 넣음)
├── data/               데이터 (2번)
└── src/
    ├── agents/         analyzer · retriever · rewriter · verifier · report  (단계별 파일, 아직 비어 있음)
    ├── graph/
    │   ├── state.py    MigrateState  (단계끼리 주고받는 정보 모양)
    │   ├── nodes/      (비어 있음)
    │   └── supervisor.py  StateGraph 틀 (노드 연결 전)
    ├── prompt/         AI에게 줄 지시문 (비어 있음)
    └── rag/            검색 관련 (2번)
```

**State 읽는 법**: 지금 `MigrateState`는 `old`(옛 위치), `new`(새 위치), `evidence_id`(근거 ID), `kind`(native / classic_fallback)로, **이사 한 건**의 모양입니다. 2번 대응표의 한 줄과 딱 맞습니다. 그래프 전체가 주고받을 정보(입력 코드, 근거 목록, 새 코드, 검증 결과, 시도 횟수)는 1번이 앞으로 채울 것으로 보입니다 → **회의 질문거리**.

### 2번이 추가한 것 (2번 브랜치, PR 예정)

2번이 공유한 데이터 출처 4가지와 실제 파일을 맞춰 보면 이렇습니다.

| 단계 | 2번이 말한 출처 | 하는 일 | 폴더 | 결과 |
|---|---|---|---|---|
| 1 | PyPI 패키지 코드 + langchain-cli 변환 규칙 | 버전별 도구 목록을 뽑아 **import 대응표** 만들기 (`@deprecated` 정보, 대안 포함) | `src/rag/import_map/` | `import_map.jsonl` 9,155줄 |
| 2 | 최신 공식 문서 (v1 마이그레이션 가이드 포함) | docs.langchain.com Python 문서 수집 | `src/rag/docs_collect/` | 271개 |
| 3 | 구버전 마이그레이션 가이드 (0.3.30 태그) | 체인 · 메모리 · 에이전트 옮기는 법 문서 수집 | 〃 | 24개 |
| 4 | – | 검색하기 좋게 **조각(청크)** 내기 | `src/rag/chunking/` | `chunks.jsonl` 11,903개 |
| 5 | – | 조각을 숫자로 바꿔(**임베딩**) **벡터 DB(Chroma)**에 저장 | `src/rag/embedding/` | `data/vectordb/chroma/` |
| 6 | – | **검색기**: 이사 목록 정확 매칭 + 문서 하이브리드 검색 | `src/rag/retrieval/` | `retrieve()` → 근거 목록 |

**검색기가 돌려주는 것 (근거 한 개의 모양)**: `evidence_id`(근거 ID), `source`(대응표 / 최신 문서 / 옛 가이드), `text`(내용), `url`(문서 링크, 문서 근거만), `old` · `new` · `kind` · `alternative`(대응표 근거만), `score`(점수). → 3번이 이걸 받아 고치고, 4번 화면은 이걸로 **"근거"**를 보여 줍니다.

## 5장. 프로젝트 지금 평가 (2026-10-13 오후)

**한 줄 평가**: 재료(2번)는 탄탄하게 준비됐고, 이제 **요리(3번)와 동선(1번)**이 따라붙어야 하는 시점입니다. 4번은 이 사이에 **평가 준비**를 해 두면 순서를 지키면서도 늦지 않습니다.

## 6장. 3번과 4번의 역할 (팀 코드 기준)

| | 3번 변환 · 검증 | 4번 화면 · 평가 |
|---|---|---|
| 위치 | **챗봇 안** (②와 ⑤ 사이) | **챗봇 바깥** |
| 받는 것 | 2번 검색기의 근거 목록, 1번 State | 챗봇의 최종 결과(⑤ report) |
| 하는 일 | ① import 뽑기 ③ AI로 고쳐 쓰기 ④ 실행해서 확인, 실패하면 다시 | 화면에 보여 주기, 일반 AI와 같은 문제로 비교, 보고서 · 발표 |
| 만드는 파일 | `src/agents/analyzer.py`, `rewriter.py`, `verifier.py`, `src/prompt/` | `app.py`, 평가 폴더(새로), 보고서 · README · 발표 |
| 둘이 맞출 것 | **검증 기준**: 어디까지 확인하나 (import만 / 기능 이름까지) | 같은 기준으로 채점해야 비교가 공정함 |
| 둘이 맞출 것 | **결과 모양**: report에 무엇이 담기나 | 화면에 무엇을 보여 줄지 |

**report(⑤)는 누가?** 아직 정하지 않았습니다. 3번이 처음에 "평가 쪽에 report까지 들어간다"고 생각했었으니, 회의에서 정하면 됩니다.

## 7장. 4번에게 필요한 역량

| 역량 | 왜 필요한가 | 지금 필요한 수준 | 연습 방법 |

## 9장. 최근 팀 대화 정리 (역할 번호로)

## 10장. 용어 · 기술 사전

| 용어 | 쉬운 뜻 | 팀 프로젝트에서 |

| LangChain | AI 앱을 만드는 파이썬 도구 세트 | 고쳐 줄 대상 |

| RAG | 자료를 찾아보고 답하기 | ② retriever |
| 청크(조각) | 문서를 검색하기 좋게 자른 조각 | 11,903개 |
| 임베딩 | 글을 숫자 목록으로 바꿔 "뜻이 비슷한 것"을 찾게 함 | OpenAI `text-embedding-3-small` |
| 벡터 DB (Chroma) | 임베딩을 저장하고 비슷한 것을 찾는 창고 | `data/vectordb/chroma/` |
