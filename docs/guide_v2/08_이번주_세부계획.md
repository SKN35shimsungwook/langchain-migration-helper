# 이번 주 세부 계획 (4번)

> **최신 버전 · 2026-10-13** · 마감: 이번 주 안 (금요일 발표 가정)  
> 화면 저장소: [migration-chatbot-ui](https://github.com/SKN35shimsungwook/migration-chatbot-ui) (팀 저장소와 같은 구조) · 오늘 회의록: [2026-10-13 주간회의](../meetings/2026-10-13_주간회의.md)

## 이것 세 줄만 기억해도 됩니다

1. 지금은 결과물(챗봇)이 없으니 **화면 큰 틀 → 문서(회의록 · 보고서 · 발표) 준비**가 먼저입니다. 평가는 챗봇이 나온 뒤에 합니다.
2. 화면은 **가짜 결과로 먼저 돌아가게** 만들었고, 근거는 2번 대응표가 있으면 **실제 근거**를 씁니다. 챗봇 연결은 `src/ui/client.py` **한 곳**만 바꾸면 됩니다.
3. 팀 저장소에는 **1번에게 확인받은 뒤 4번이 직접** 옮깁니다.

## 1장. 오늘 만든 화면

**구성: 채팅 + 결과 패널**

| 위치 | 내용 |
|---|---|
| 사이드바 | 목표 버전(LangChain 1.x), 연결 상태 배지, 예제 3개(쉬움 · 중간 · 어려움), 대화 지우기 |
| 왼쪽 채팅 | 옛 코드 붙여 넣기 → 진행 단계 ①~⑤ 표시 → 한 줄 요약 |
| 오른쪽 결과 | 검증 배지 · 목표 버전 · 근거 출처, 탭 3개(전후 비교 / 변경표 · 근거 / 진행 과정) |
| 다른 탭 | 비교(평가 자리, 준비 중), 프로젝트 소개(발표 데모용) |

**확인한 것**: 예제 3개 모두 오류 없이 동작, LangChain 코드가 아닐 때 안내 문구, 팀 저장소 구조에 2번 데이터를 같이 둔 임시 사본에서 **실제 근거 ID(`imap-…`)**가 표시됨.

## 2장. 이번 주 일정

| 날 | 화면 | 문서 | 기다리는 것 |
|---|---|---|---|
| **화 (오늘)** | ✅ 큰 틀 완성, 새 저장소에 올림 | ✅ 회의록, 이 계획 | – |
| **수** | 2번 PR이 dev에 합쳐지면 팀 저장소에서 켜 보고 **실제 근거 확인** → 1번 확인 후 4번 브랜치에 PR | **보고서 목차 뼈대** + "데이터" 장 채우기 (2번이 공유한 출처 4가지) | 2번 PR, 1번 답 |
| **목** | 1번 그래프 · 3번 결과가 나오면 `client.py` 연결. 안 나오면 가짜 결과 + 실제 근거로 데모 준비 | **발표 자료 뼈대**: 문제 → 해결 → 구조 → 데모 → 결과 자리 → 한계 | 1 · 3번 |
| **금** | 데모 녹화 (현장 실패 대비) | 결과 채우기, 리허설 | 챗봇 완성 여부 |

**평가는?** 챗봇이 목요일까지 나오면 **같은 옛 코드 몇 개로 일반 AI와 간단 비교**를 해서 비교 탭과 발표에 넣습니다. 안 나오면 발표에는 **"평가 계획"**으로 넣습니다.

## 4장. 문서 준비 (중간중간)

| 문서 | 언제 | 내용 |
|---|---|---|
| 회의록 | 매 회의 | 정한 것 · 공유된 것 · 다음까지 확인할 것 (역할 번호로) — `docs/meetings/` |
| 보고서 | 수 뼈대 → 금 완성 | 문제, 해결 방법, 데이터(2번), 구조(1번), 변환 · 검증(3번), 화면 · 평가(4번), 결과, 한계 |
| 발표 자료 | 목 뼈대 → 금 완성 | 문제 → 해결 → 구조 → 데모 → 결과 → 한계 → 팀 |

## 5장. 위험과 대비

| 위험 | 대비 |
|---|---|
| 챗봇이 금요일까지 완성되지 않음 | 화면은 가짜 결과 + **실제 근거**로 데모, 평가는 계획으로 발표 |
| `app.py`를 1번이 다른 용도로 쓰려 함 | 화면을 다른 파일 이름으로 두기 (`pages/` 등) |
| 결과 모양이 화면과 다름 | `client.py` 한 곳에서 모양을 바꿔 맞춤 |
| 현장 데모 실패 | 금요일에 녹화본 준비 |
