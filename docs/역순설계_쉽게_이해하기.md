# 거꾸로 생각하면 쉬워요: 역순 설계로 보는 우리 프로젝트

> 초등학생도 이해할 수 있게 쓴 설명서입니다.
> **역순 설계**란 "마지막에 무엇을 보여줄지"를 먼저 정하고, 거기서부터 거꾸로 "그걸 하려면 뭐가 필요하지?"를 따라 내려가는 방법이에요.

---

## 0. 먼저, 이 프로젝트는 무슨 이야기일까?

### 옛날 맞춤법만 아는 친구

반에 글씨를 아주 잘 쓰는 친구가 있어요. 그런데 이 친구는 **옛날 책만 많이 읽어서** 옛날 맞춤법으로 써요.
선생님이 "요즘 맞춤법으로 고쳐 와"라고 해도, 옛날 방식으로 고쳐 오고, **자기가 틀린 줄도 몰라요.**

여기서 친구는 **ChatGPT 같은 AI**이고, 맞춤법은 **LangChain이라는 프로그램 도구의 사용법**이에요.
LangChain은 2025년에 1.0 버전으로 크게 바뀌었는데, 인터넷에는 옛날 사용법이 훨씬 많아요.
그래서 AI는 옛날 방식으로 코드를 써 주고, 그 코드는 실행하면 고장이 나요.

### 우리가 만드는 똑똑한 친구

우리가 만드는 프로그램은 이렇게 해요.

1. **사전을 찾아봐요.** 최신 공식 설명서(문서)를 검색해요. → "문서 근거"
2. **직접 써 보고 확인해요.** 고친 코드를 최신 LangChain에서 실제로 돌려 봐요. → "실행 근거"
3. **틀리면 다시 고쳐요.** 에러가 나면 그 에러를 힌트 삼아 사전을 다시 찾고, 또 고쳐요. (최대 3번)

---

## 1. 거꾸로 따라가기: 마지막 장면부터

발표하는 날, 우리가 보여주고 싶은 **마지막 장면**은 딱 하나예요.

> 🏆 **"같은 문제 30개를 줬더니, 일반 AI보다 우리 프로그램이 더 많이 맞혔어요!"**

이 장면을 만들려면 무엇이 필요할까요? 계단을 한 칸씩 내려가 봐요.

```text
🏆 발표: "우리가 더 많이 맞혔어요!"
 ↑ 이걸 보여주려면
📊 그래프 (누가 몇 % 맞혔는지)
 ↑ 그래프를 그리려면
📝 성적표 (문제마다 맞았는지 틀렸는지 적은 파일)
 ↑ 성적표를 만들려면
✅ 채점하기 (정답인지 확인하는 방법)
 ↑ 채점하려면
📋 채점 규칙 + 📄 시험지 30문제
 ↑ 시험지를 만들려면
📚 LangChain이 무엇이 바뀌었는지 알기 (자료 조사)
```

이제 맨 아래 계단부터 올라가면서, **계단마다 우리가 만든 파일**을 짝지어 볼게요.

---

## 2. 계단마다 무엇을 만들었나

### 계단 1. 📚 자료 조사: "무엇이 바뀌었지?"

시험지를 만들려면 먼저 LangChain이 어떻게 바뀌었는지 알아야 해요.
최신 공식 설명서, 옛날 버전 설명서, 비슷한 연구 논문이 어디 있는지 찾아서 정리했어요.

- 만든 파일: [데이터_출처_조사.md](데이터_출처_조사.md)
- 쉽게 말하면: **도서관에서 어떤 책을 빌려야 하는지 목록을 만든 것**

### 계단 2. 📄 시험지 30문제

옛날 방식으로 쓴 LangChain 코드 30개를 만들었어요.

| 난이도 | 개수 | 비유 |
|---|---|---|
| 쉬움 | 10개 | 낱말 하나만 바뀐 문제 (주소만 바뀜) |
| 중간 | 10개 | 문장 구조를 바꿔야 하는 문제 (체인 구조 변경) |
| 어려움 | 10개 | 글 전체를 새로 써야 하는 문제 (에이전트 구조 변경) |

**중요한 점**: 시험지에 넣은 30문제가 정말로 "최신 LangChain에서 고장 나는지" 하나하나 직접 확인했어요.
이미 맞는 문제를 내면 시험의 의미가 없으니까요.

- 만든 파일: [eval/testset.json](../eval/testset.json) (시험지), [eval/check_testset.py](../eval/check_testset.py) (시험지 검사기)
- 쉽게 말하면: **시험 문제를 내고, 문제가 제대로 만들어졌는지 검사하는 기계까지 만든 것**

### 계단 3. 📋 채점 규칙

공정하게 비교하려면 규칙이 필요해요. 달리기 시합에서 두 사람이 **같은 출발선, 같은 거리**를 뛰어야 하는 것처럼요.

- 일반 AI와 우리 프로그램은 **같은 AI 두뇌(모델)**를 쓴다.
- **같은 30문제**를 **같은 순서**로 푼다.
- **같은 채점기**로 채점한다.
- 꼼수는 틀린 것으로 친다. (예: 어려운 부분을 통째로 지워서 에러를 없앤 경우)

- 만든 파일: [eval/EVAL_RULES.md](../eval/EVAL_RULES.md)
- 쉽게 말하면: **시합 규칙표**

### 계단 4. ✅ 채점하기

고친 코드를 최신 LangChain에서 실제로 실행해 봐요. 에러가 안 나면 ⭕, 에러가 나면 ❌예요.
AI에게 "이거 맞아?"라고 묻지 않아요. 그 AI도 옛날 맞춤법만 알 수 있으니까요. **직접 돌려 보는 게 가장 확실해요.**

- 만든 파일: [eval/verify.py](../eval/verify.py)
- 쉽게 말하면: **빨간 펜 선생님 로봇** (누가 풀었든 똑같은 기준으로 채점)

### 계단 5. 📝 성적표

일반 AI에게 30문제를 풀게 하고, 채점 로봇으로 채점해서 성적표 파일로 저장해요.
우리 프로그램도 똑같이 해요.

- 만든 파일: [eval/run_baseline.py](../eval/run_baseline.py) (일반 AI가 시험 보는 기계)
- 결과가 저장되는 곳: `eval/results/`
- 쉽게 말하면: **비교 상대(일반 AI)를 시험 보게 하는 기계**. "baseline(베이스라인)"은 **비교 기준**이라는 뜻이에요.

### 계단 6. 📊 그래프

성적표를 그림으로 바꿔요. 숫자만 보면 어렵지만 막대그래프로 보면 한눈에 알 수 있어요.

| 그래프 | 보여주는 것 |
|---|---|
| 난이도별 성공률 | 어려운 문제일수록 우리가 훨씬 잘하나? |
| 시도 횟수별 성공률 | "틀리면 다시 고치기"가 정말 도움이 됐나? |
| 성공의 질 | 맞았지만 곧 고장 날 수 있는 답은 얼마나 되나? |

- 만든 파일: [eval/make_charts.py](../eval/make_charts.py)
- 쉽게 말하면: **성적표를 그림으로 바꾸는 기계**

### 계단 7. 🏆 발표

그래프를 들고 발표해요. 그리고 모든 내용을 [README.md](../README.md)에 정리해서 누구나 볼 수 있게 했어요.

## 3. 실험하다가 알게 된 신기한 것

### 🔔 "곧 문 닫아요" 경고

LangChain 가족 중 `langchain-community`라는 꾸러미는 **불러오기만 해도** "곧 관리를 그만둬요"라는 경고를 내요.
가게 문에 "이번 달까지만 영업합니다"라고 붙어 있는 것과 같아요. 지금은 물건을 살 수 있지만, 곧 못 사게 돼요.
그래서 이런 코드는 "맞았지만 곧 고장 날 수 있는 답"으로 따로 셌어요.

### 🚪 뒷문으로 들어가기

옛날 기능을 `langchain_classic`이라는 "옛날 물건 보관함"에서 꺼내 쓰면 에러는 안 나요.
하지만 요즘 방식으로 고친 건 아니에요. 그래서 이것도 따로 셌어요.

## 4. 한 장으로 정리

```text
문제:  AI가 옛날 방식 코드를 주고, 틀린 줄도 모른다
해결:  사전 찾기(문서) + 직접 돌려 보기(실행) + 틀리면 다시 고치기
증명:  같은 시험지 30문제로 일반 AI와 시합 → 그래프로 보여주기

만든 순서 (거꾸로 생각한 순서의 반대):
  자료 조사 → 시험지 → 채점 규칙 → 채점 로봇 → 시험 보기 → 그래프 → 발표
```

**역순 설계의 좋은 점**: 마지막에 보여줄 장면을 먼저 정했기 때문에, 필요 없는 일은 안 하고 꼭 필요한 일만 순서대로 할 수 있었어요.
